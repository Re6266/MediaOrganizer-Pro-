# MediaOrganizer-Pro 项目周报

**周报周期：2026年11月2日—2026年11月8日**
**编写日期：2026年11月7日（工作记录截至当日）**
**本周主负责人：B**
**本周主题：本地媒体扫描与元数据提取**

## 一、本周工作进展

1. **完成本地媒体选择与扫描流程。** 在第一周 Python、Streamlit、SQLite 基础上新增扫描模块。支持 Windows 系统文件选择窗口和文件夹选择窗口；文件支持单选、多选，文件夹支持递归发现子文件夹中的文件。文件和文件夹选择采用互斥的待扫描状态，确认扫描或取消后可以开始下一批选择。
2. **完成图片与视频基础信息提取。** 图片读取文件大小、分辨率和 EXIF 原始拍摄时间；视频读取大小、分辨率、播放时长，并增加录制时间元数据检测。缺少拍摄或录制时间时保留空值，界面显示未知，不以文件保存时间或扫描时间替代。
3. **完成缩略图生成。** 图片经方向校正后生成缩略图，视频读取首帧生成缩略图，最大尺寸为 256×256，保存到项目缩略图目录。原文件预览与缩略图分别处理。
4. **完成 SQLite 索引保存。** 扫描结果写入现有 media 表，以文件路径作为唯一标识；重复扫描同一路径更新基础信息。新增 media_thumbnails 表关联媒体与缩略图，新增 video_date_metadata 表记录视频时间检测状态及独立的创建时间信息。
5. **完成扫描与检查页面。** 新增第二周预览入口，支持扫描前查看所选文件、预览和排除单个文件，扫描后按行显示文件名、类型和大小，支持预览原始图片、播放视频及查看详细属性。最近添加按每页 20 条展示，移出索引需确认且保留原文件。
6. **完善异常处理和操作反馈。** 分别统计扫描成功、失败和忽略的文件；单个损坏文件不阻断其他文件处理。原文件被删除或移动时提示不可用，不自动清理记录。单次选择上限为 100 个文件，文件夹连同子文件夹内的所有文件计数；超限整批拒绝，不产生部分索引。该数值为当前界面的保守限制，并非性能测试得出的最大容量。
7. **调整显示适应性。** 根据实际试用反馈调整浅色页面中的按钮、预览、展开区域和页码控件配色，并限制媒体预览尺寸，改善横竖屏媒体的查看体验。

## 三、本周关键决策及理由

1. **沿用第一周公共基础文件。** 保留 app.py、config.py、database.py、models.py，在新增模块和页面中实现本周功能，降低覆盖其他组员代码的风险；依赖文件追加 pymediainfo。
2. **按指定职责拆分模块。** modules/scanner.py 负责发现文件、扫描调度和索引入库；modules/metadata_extractor.py 负责元数据读取；modules/thumbnail_generator.py 负责缩略图生成，便于后续检测、分组与浏览模块复用。
3. **采用本地索引模式。** 当前扫描直接读取用户选择的原始路径，不默认复制原图或视频。缩略图是显示缓存，不能作为原文件备份。源文件消失时保留索引并提示不可用。
4. **区分拍摄时间、创建时间、入库时间与播放时长。** 只将明确标识的拍摄或录制时间写入 capture_time，避免对后续按时间分组产生误导；工具可读取的信息并不保证等于真实拍摄时间。
5. **将运行依赖纳入项目安装流程。** 用 requirements-week2.txt 声明视频元数据读取库，减少用户手动安装外部工具的步骤；本机测试依赖目录不提交到仓库。
6. **使用 AI 辅助并结合实际验证。** AI 用于方案讨论、代码实现及测试辅助；通过本机试用反馈调整原生选择窗口、配色、媒体预览和文件排除交互。时间解析测试使用模拟数据。
